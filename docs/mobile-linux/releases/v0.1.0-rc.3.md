# Mobile Linux SDK v0.1.0-rc.3

Binary source: `6b033d41a2b6b736fda1e8f996f55a4b20bd885d` (clean checkout).
The public root Swift package on this release references these Release binaries;
its wrapper commit follows the binary source commit.

Guest sessions use `lingxi`, UID/GID 1000, `HOME=/home/lingxi`, and default cwd
`/home/lingxi/lingxi`. Passwordless sudo and persistent user/admin homes are included.
The product's iOS construction/dispatch stack fixes live in Harness, not SDK binaries.

Assets at https://github.com/lingxi-coder/mobile-linux-runtime/releases/tag/v0.1.0-rc.3:

- Complete Android Maven SDK, version `0.1.0-rc.3`, with arm64-v8a/x86_64 Rust FFI.
- Rust-host-only installer/native-support Maven bundle, version `0.1.0`, with no second Rust core.
- Android native-support bundle with both ABIs, licenses and an exact file manifest.
- iOS FFI and NativeSupport XCFrameworks: device arm64, simulator arm64/x86_64.
- Standalone Swift package archive, plus the tagged Git package.
- Android rootfs `3.24.2-user1` for both ABIs, with complete per-ABI evidence.
- iOS `3.24.2-user1` staging bundle: portable manifest, the tested fakefs archive,
  RootfsPatch bundle and vDSO. The iOS base image does not claim the Android toolchain profile.
- `SHA256SUMS`, `release-provenance.json`, and `rootfs-provenance.json`.

All SDK binaries use Release profiles. The release provenance reports
`validation_only: false`. Original third-party licenses and source/patch identities
remain included. Rootfs archives are explicit embedding inputs, outside the SDK core.

The complete LingXi product was physically checked on Samsung SM_S9310 (API 36)
and iPhone 11 (iOS 18.6.2) for identity, sudo, project mounts, background execution,
PTY and persistent home across process restarts. Those product checks used the same
SDK source; the SDK FFI archives here were rebuilt in Release mode, and their generated
bindings were checked against every target library. This does not claim an x86 Android
emulator guest run or a repeat of every physical-device test against these SDK sample binaries.
